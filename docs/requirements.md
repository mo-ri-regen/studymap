# StudyMap 要件定義書（v0.5）

最終更新: 2026-10-31

## 1. 概要

資格試験の勉強で「1日に何問解けばいいか」「いつ受験すればいいか」を計算し、日々の進捗に合わせて計画を見直せるWebアプリ。

### 背景・課題

- 問題集の総問題数は分かっていても、試験日までに1日何問やればいいか毎回手計算している
- 逆に「1日これくらいなら続けられる」というペースから、いつ受験するのが現実的か分からない
- 計画を立てても、遅れたときにどれだけ挽回が必要か分からず、挫折しやすい

### ゴール

- 入力から30秒以内に「1日の目標問題数」または「受験可能な時期」が分かる
- 毎日の記録から、計画に対して進んでいるか遅れているかが一目で分かる
- 遅れや前倒しに合わせて、残りの計画が自動で引き直される

### 想定ユーザー

- 問題集・過去問を中心に勉強する資格受験者（例: 基本情報技術者、簿記、宅建など）
- 社会人など、勉強できる曜日や時間が限られている人

## 2. 機能要件

### 2.1 MVP（最初のバージョン）

| ID   | 機能                              | 内容                                                                                                                                                       |
| ---- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 | 学習プラン作成                    | 資格名、教材（問題集）、総問題数、周回数、開始日、学習する曜日、休みの日、1日の上限問題数（初期値50問）を登録する                                          |
| F-02 | 試験日から逆算（モードA）         | 試験日を入力すると、1日あたりの目標問題数を出す                                                                                                            |
| F-03 | ペースから受験日を算出（モードB） | 1日に解ける問題数を入力すると、完了予定日と受験おすすめ時期を出す                                                                                          |
| F-04 | 予備日（バッファ）設定            | 試験直前の見直し期間や予備日を日数で設定し、計算に反映する                                                                                                 |
| F-05 | 進捗記録                          | 「+1」「+5」「+10」ボタンで解いた数を足していく方法と、1日の合計を数字で入力する方法の両方で記録できる。過去の日の記録も後から修正できる                   |
| F-06 | 計画の再計算                      | 実績をもとに残りの問題数・日数から目標を引き直す                                                                                                           |
| F-07 | 進捗の見える化                    | 最初の計画・立て直した計画・実績のグラフ、達成率、遅れ/前倒しの問題数、完了見込み日を表示する                                                              |
| F-08 | 今日のやること                    | トップ画面で「今日の目標○問」と残り日数を表示する                                                                                                          |
| F-09 | 完了画面                          | 試験日を過ぎたとき、または全部解き終わったときに「おつかれさまでした」と、合計問題数・勉強した日数・進捗グラフを表示する。「新しい計画を作る」ボタンを置く |
| F-10 | データの書き出し・読み込み        | 計画と記録をファイルに書き出し、そのファイルから読み込める。ブラウザのデータが消えたときの備えと、端末の移動に使う                                         |

- MVPで持てる計画は1つだけ。新しい計画を作ると今の計画と記録は置き換わるため、作る前に確認を出し、書き出しをすすめる

### 2.3 入力チェック

次の入力は受け付けない。入力欄のすぐ下に理由を表示し、直すまで次に進めないようにする。

| 入力                                                        | 表示する理由の例                                                 |
| ----------------------------------------------------------- | ---------------------------------------------------------------- |
| 試験日が開始日より前                                        | 試験日は開始日より後にしてください                               |
| 勉強する曜日が0日                                           | 勉強する曜日を1日以上選んでください                              |
| 総問題数・周回数・1日の問題数が0以下                        | 1以上の数を入れてください                                        |
| 勉強できる日が1日も残っていない（休み・予備日を除いた結果） | 勉強できる日がありません。試験日・曜日・予備日を見直してください |

### 2.2 将来の拡張（MVP後）

- 複数の資格・複数教材をまとめて管理
- ログイン（アカウント）とクラウド保存、端末をまたいだ同期
- 試験日程データ（年2回など）から受験回を候補表示
- 正答率の記録と、苦手分野の周回を増やす計画
- 問題数以外の単位（ページ数、勉強時間）への対応
- 周回ごとにペースを変える（例: 2周目は1.5倍速く解ける）
- カレンダー連携（Googleカレンダーへの書き出し）
- リマインド通知

## 3. 計算ロジック

### 共通の考え方

- **総作業量** = 総問題数 × 周回数
- **学習可能日数** = 開始日〜最後の学習日のうち、学習する曜日に該当し、休みの日を除いた日数
- **最後の学習日** = 試験日の（予備日数 + 1）日前。試験日の当日は学習日に数えない
  - 例: 試験日 11/30・予備日 7日 → 11/23〜11/29 が予備日、最後の学習日は 11/22

### モードA: 試験日 → 1日の目標

- 1日の目標問題数 = ⌈ 総作業量 ÷ 学習可能日数 ⌉
- プランで設定した1日の上限問題数（初期値50問）を超える場合は「この日程は厳しい」と警告を出す

### モードB: 1日のペース → 受験日

- 必要学習日数 = ⌈ 総作業量 ÷ 1日の問題数 ⌉
- 開始日から学習曜日だけを数えて必要日数に達した日を「完了予定日」とする
- 完了予定日 + 予備日数 を「受験おすすめ日（この日以降）」として出す

### 日ごとの割り振り

- 割り切れないときは、前の日から1問ずつ多く配る（例: 100問を3日 → 34・33・33問）
- これにより、計画の合計は総作業量とぴったり一致する

### 再計算（進捗記録後）のルール

|     | 決めたこと                               | ルール                                                                                                                          |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| ①   | 進捗グラフの計画の線                     | 2本引く。最初の計画（実線）と、今日から立て直した計画（点線）                                                                   |
| ②   | 予定とずれたときの毎日の目標             | 遅れたら増やす。進んでいても減らさず、「予定より○日早く終わりそう」と表示する。今日の目標は、記録を入れても今日のうちは変えない |
| ③   | 途中で試験日・学習曜日・休みを変えたとき | 新しい設定で最初の計画を作り直す。記録は消さずに残す                                                                            |
| ④   | 割り切れないときの配り方                 | 前の日から1問ずつ多く配る                                                                                                       |
| ⑤   | 休みの日（学習曜日以外）に解いた分       | 進んだ分として数える                                                                                                            |

計算方法:

- 残り作業量 = 総作業量 − 実績の合計
- 残り日数 = 明日以降の学習可能日数（最後の学習日まで）
- 挽回に必要な1日分 = 残り作業量 ÷ 残り日数（④のルールで割り振る）
- 明日以降の1日の目標 = 「最初の計画の、その日の目標」と「挽回に必要な1日分」の大きいほう。ただし残り作業量より多くはしない
- 今日の目標 = その日の始まりの時点で決めた数（今日の記録では変わらない）
- 計画との差（遅れ/前倒し）= 今日までの最初の計画の累計 − 実績の累計
- 前倒しのときは、明日以降も目標どおり進んだ場合の完了見込み日を出し、「予定より○日早く終わりそう」と表示する

> 計算ロジックはUIから切り離した純粋な関数にまとめ、単体テストで端数・休日・境界値を確認する。

## 4. 画面一覧

| 画面                     | 内容                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------ |
| トップ（ダッシュボード） | 今日の目標、残り日数、達成率、進捗グラフ                                             |
| プラン作成               | ステップ形式の入力フォーム（教材 → 日程 → 結果プレビュー）                           |
| 計算結果                 | モードA/Bの結果、日ごとの計画表、警告                                                |
| 記録                     | 今日の問題数を入力（ボタンで足す／合計を入力）、過去の記録の一覧・修正               |
| 完了                     | おつかれさまメッセージ、合計問題数、勉強した日数、進捗グラフ、新しい計画を作るボタン |
| 設定                     | 学習曜日・休日・予備日の変更、データの書き出し・読み込み・リセット                   |

- スマホでの利用を優先したレスポンシブ対応
- 初めて見た人がすぐ試せるよう、サンプルデータで始められるボタンを用意する

## 5. データ（MVP）

- **Plan**: id, 資格名, 教材名, 総問題数, 周回数, 開始日, 試験日 or 1日の問題数, モード, 学習曜日, 予備日数
- **Holiday**: planId, 日付
- **Record**: planId, 日付, 解いた問題数, メモ

MVPはログインなしでブラウザ（localStorage）に保存する。ポートフォリオを見る人が登録なしで触れることを優先する。保存処理は差し替えやすい形にしておき、将来クラウド保存に移せるようにする。

## 6. 非機能要件

- **使いやすさ**: 主要操作は3タップ以内、入力エラーはその場で分かりやすく表示
- **性能**: 初回表示2秒以内（Lighthouse Performance 90以上を目標）
- **アクセシビリティ**: キーボード操作、色だけに頼らない表示（Lighthouse Accessibility 90以上）
- **品質**: 計算ロジックのテストカバレッジ90%以上、主要フローのE2Eテスト
- **対応ブラウザ**: 最新の Chrome / Safari / Edge（スマホ含む）

## 9. 決定事項

| 項目                   | 決定内容                                                 |
| ---------------------- | -------------------------------------------------------- |
| アプリ名               | StudyMap で確定                                          |
| 1日の上限問題数        | プランごとにユーザーが設定できる。初期値は50問           |
| 学習量の単位           | MVPは問題数のみ。ページ数・時間は将来の拡張              |
| 周回ごとのペース       | MVPは全周回同じペース。周回ごとの変更は将来の拡張        |
| 公開URL                | まずは Vercel の標準ドメイン。独自ドメインは公開後に検討 |
| 計画の数               | MVPは1つだけ。複数の計画は将来の拡張                     |
| 記録の入れ方           | ボタンで足す方法と、合計を入力する方法の両方             |
| 試験日後・完了後の表示 | 完了画面を出す                                           |
| おかしな入力           | 入力できなくし、理由をその場で表示する                   |
| 書き出し・読み込み     | MVPに入れる                                              |
